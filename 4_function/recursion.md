## Рекурсия в математике

Факториал $n!$ задается **рекуррентной формулой**:
<!--
$$ n! =
  \begin{cases}
   1       			& \quad n=0 \\
   n \cdot (n-1)!  	& \quad n>0
  \end{cases}
$$  
-->
$$ n! = \begin{cases}   1       			& \quad n=0 \\\\   n \cdot (n-1)!  	& \quad n>0  \end{cases} $$  

То есть 
<!--
$$ f(n) =
  \begin{cases}
   1       			& \quad n=0 \\ 
   n \cdot f(n-1)  	& \quad n>0
  \end{cases}
$$  
-->
$$ f(n) =  \begin{cases}   1       			& \quad n=0 \\\\    n \cdot f(n-1)  	& \quad n>0  \end{cases} $$  

Обратите внимание на две части этого определения:

* **Рекурсивный случай** при $n > 0$ выражается через факториал меньшего числа.
* **Базовый случай** при $n = 0$ известен сразу, 1. Дальше углубляться некуда.

Функция, которая вызывает саму себя, называется **рекурсивной**.

Шаблон для написания любой рекурсивной функции:

* **Базовый случай**, когда ответ известен сразу.
* **Рекурсивный случай**, когда задача сводится к такой же, но *меньшей* задаче.

### Первая попытка: код, который падает

Напишем "в лоб" определение факториала:

```cpp
#include <stdio.h>

int fact (int n) { 
	int res = n * fact (n-1); 		// из fact вызывается fact - рекурсия
	return res;
} 
int main ( ) { 
	printf("4! = %d\n", fact(4)); 	// из main вызывается fact
	return 0; 
}
```

Однако, при запуске программы получаем

```cpp
Segmentation fault (core dumped)
```
Что случилось?

<i>Для простоты чтения кода везде будем использовать тип int. В задачах, однако, стоит подумать - какие типы стоит использовать, чтобы вычислить максимально представимый факториал.</i>

## Что хотим получить?

<p style="text-align:center"><img alt="" height="363" src="https://stepik.org/media/attachments/lesson/261699/fact_call.svg" width="400" /></p>

Это пример **линейной рекурсии**. На каждом уровне **не более одного** рекурсивного вызова. Результат вызова используется как есть или после простого преобразования. Дерево вызова функций - цепочка (линия). 

### Как работает рекурсивный вызов функции

Добавим в функцию отладочную печать:
```cpp
int fact (int n) {
	printf("call fact(%d)\n", n);
	int res = n * fact (n-1); 			// из fact вызывается fact - рекурсия
	printf("return %d! = %d\n", n, res);
	return res;
} 
```
Запустим код и получим:
```cpp
call fact(4)
call fact(3)
call fact(2)
call fact(1)
call fact(0)
call fact(-1)
call fact(-2)
call fact(-3)
```
и так далее, все дальше углубляясь в отрицательные числа. Почему так происходит?

Что происходит при вызове из функции `main` этой функции `fact(4)`?

* управление передаётся в `fact`;
* создаются новые переменные `n = 4` и `res`. Они живут, пока этот вызов не завершится;
* начинается вычисление `n * fact(n - 1)`, то есть вызывается `fact(3)`, при этом **вызов `fact(4)` еще не завершается**;
* при вызове `fact(3)` создаются свои `n = 3` и `res`, ..., вызывается `fact(2)`
* ...
* при вызове `fact(0)` создаются свои `n = 0` и `res`, ..., вызывается `fact(-1)` и далее, далее и далее...
* и так далее вызывается `fact(-2)`, `fact(-3)` до тех пор, пока есть возможность создать новые экземпляры переменных `n` и `res`, ибо для каждого вызова функции `fact` создаются свои переменные `n` и `res`, пока не закончится доступная память. Дальше программа упадет. 

Благодаря созданию нового экземпляра переменной `n` при каждом вызове и возможен рекурсивный вызов функции.

Но мы не можем остановиться. Что делать?

## Добавляем базовый случай

Главное в рекурсии - вовремя остановиться. В этом нам поможет базовый случай.

Мы забыли часть математического определения факториала $0! = 1$.

Переведем на язык Си фразу "Если n=0, то результат 1".

```cpp
int fact (int n) {
	printf("call fact(%d)\n", n);
	if (n == 0) {
		printf("zero! = 1\n");
		return 1;
	}
	int res = n * fact (n-1); 			// из fact вызывается fact - рекурсия
	printf("return %d! = %d\n", n, res);
	return res;
} 
```
Запустим код и получим:
```cpp
call fact(4)
call fact(3)
call fact(2)
call fact(1)
call fact(0)
zero! = 1
return 1! = 1
return 2! = 2
return 3! = 6
return 4! = 24
```

Видно, что первым был вызван `fact(4)`, который закончился в самую последнюю очередь.

## Отладочная печать с отступами

Хочется наглядно увидеть, когда начинается вызов `fact(4)` и когда он заканчивается. Для лучшей читаемости кода мы использовали отступы для каждого уровня вложенности (функция или условный оператор). Напечатаем для каждого очередного вызова функции `fact` дополнительный отступ.

Пусть уровень вложенности будет аргумент `depth`, который будет увеличиваться при каждом вложенном вызове функции.

Используем для отступов `*` в форматной строке `printf`:
```cpp
#include <stdio.h>

int fact (int n, int depth) {
	printf("%-*c call fact(%d)\n", depth, '>', n);
	if (n == 0) {
		printf("%-*c 0! = 1\n", depth, '>');
		return 1;
	}
	int res = n * fact (n-1, depth+2);
	printf("%-*c %d! = %d\n", depth, '>', n, res);
	return res; 
}
int main() {
	printf("main: 4! = %d\n", fact(4, 1));
	return 0;
}
```
получим
```cpp
> call fact(4)
>   call fact(3)
>     call fact(2)
>       call fact(1)
>         call fact(0)
>         0! = 1
>       1! = 1
>     2! = 2
>   3! = 6
> 4! = 24
main: 4! = 24
```

Такая отладочная печать гораздо понятнее.

Мы везде используем `int`, однако, $13!$ уже не умещается в `int`, а $21!$ не помещается в `unsigned long long`.

## Правила проектирования рекурсивных функций

* Определите **базовый случай**
* Сформулируйте **рекурсивный случай** - как задача сводится к меньшей.
* Убедитесь, что каждый рекурсивный вызов приближает к базовому случаю.

В `fact` базовый случай $n = 0$, аргумент $> 0$ каждый раз уменьшается на $1$, поэтому рекурсия остановится.

Всегда ли рекурсия эффективна и можно ли её заменить более простым кодом? Посмотрим на другую математическую последовательность Фибоначчи.

## Числа Фибоначчи

Последовательность чисел Фибоначчи задана формулой:
<!--
$$ 
  \begin{cases}
   fib(0) = fib(1) = 1		 & \\\\  
   fib(n) = fib(n-1) + fib(n-2)  & \quad n>1
  \end{cases}
$$  
--->
$$   \begin{cases}   fib(0) = fib(1) = 1		 & \\\\   fib(n) = fib(n-1) + fib(n-2)  & \quad n>1  \end{cases} $$  


Здесь **два базовых случая** ($n = 0$ и $n = 1$) и один рекурсивный, который сводит задачу к *двум меньшим*:

Напишем рекурсивную функцию, которая вычисляет n-тое число Фибоначчи:
```cpp
int fib(int n) {
	if (n == 0 || n == 1)
		return 1;
	return fib(n-1) + fib(n-2);
}
```
Эта функция быстро пишется по математической формуле и правильно считает. (Подумайте, какие лучше взять типы для аргумента и возвращаемого значения).

Есть ли недостатки у рекурсивных функций?

## Эффективность подсчета чисел Фибоначчи с помощью рекурсии

Добавим в функцию отладочную печать:

```cpp
#include <stdio.h>

int fib (int n, int depth) {
	printf("%-*c call fib(%d)\n", depth, '>', n);
	if (n == 0 || n == 1) {
		printf("%-*c f(0) = f(1) = 1\n", depth, '>');
		return 1;
	}
	int res = fib (n-1, depth+4) + fib (n-2, depth+4);
	printf("%-*c fib(%d) = %d\n", depth, '>', n, res);
	return res; 
}
int main() {
	int n = 4;
	printf("main: fib(%d) = %d\n", n, fib(n, 1));
	return 0;
}
```

Получим:
```cpp
> call fib(4)
>     call fib(3)
>         call fib(2)
>             call fib(1)
>             f(0) = f(1) = 1
>             call fib(0)
>             f(0) = f(1) = 1
>         fib(2) = 2
>         call fib(1)
>         f(0) = f(1) = 1
>     fib(3) = 3
>     call fib(2)
>         call fib(1)
>         f(0) = f(1) = 1
>         call fib(0)
>         f(0) = f(1) = 1
>     fib(2) = 2
> fib(4) = 5
main: fib(4) = 5
```

<p style="text-align:center"><img alt="" height="200" src="https://stepik.org/media/attachments/lesson/261699/fibonacchi_call.svg" width="436" /></p>

Видно, что алгоритм не эффективен. Много повторных вычислений `f(2)` и ещё больше `f(1)`.

Получается дерево вызова функций. Такую рекурсию называют **древовидной**. В этом случае, стоит подумать, как написать код эффективнее. Далее в курсе будут рассмотрены более эффективные варианты вычислений.

С ростом `n` сильно растет количество вызвов функции `fib`. Для `n=4` будет 9 вызовов, а для 20 уже 21891 (допишите код, чтобы он мог напечатать количество вызовов функции fib).

## Итого

* Рекурсивная функция обязана иметь **базовый случай** (условие остановки) и **рекурсивный случай** (сведение к меньшей задаче).

* Каждый рекурсивный вызов должен приближать к базовому случаю.

* Каждый вызов создаёт свои копии локальных переменных; незавершённые вызовы занимают память — при слишком глубокой рекурсии программа падает.

* Рекурсия бывает линейной (fact) и древовидной (fib); древовидная крайне неэффективна, нужно, например, запоминать уже вычисленные значения. Об этом подходе мы расскажем позже в курсе.
