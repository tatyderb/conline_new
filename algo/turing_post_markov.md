## Лекционная часть

* Только ответ "что получится в результате применения" (на какой ячейке остановится алгоритм)
* Главная сложность - нет  единой системы обозначений. Будет скриншот из эмулятора с "кодом" машины.

## Нормальные алгоритмы Маркова

* Поиск и замена
* Алфавит - набор допустимых символов
* Правила замены подстрок: было -> стало
* Начинаем каждую итерацию:
    * с первого правила
    * с начала строки
* Стоп-правило с точкой
* В начале бесконечное количество пустых строк

Задача: Удалить все нули в записи, заменить первую подстроку 111 на 222.

Вопрос: модифицировать набор правил, чтобы останавливалась, даже если нет 111 в слове.

![Удалить все нули, заменить первые 111 на 222](https://kpolyakov.spb.ru/prog/images/namwin.gif)

Заметим, что точку ставим в конце правой части. Иногда ставят в начале правой части. 

![Скриншот из лекции](https://github.com/tatyderb/conline_new/blob/refactoring/algo/img/markov.png?raw=true)

Что получится в результате применения к строке 11001 правил
```
*1 → 1* 
*0 → 0* 
1* → .1* 
0* → .0* 
   → *
```
Тут должен быть скриншот эмулятора с этой задачей.

Как удобнее делать на листочке?

* Пронумеруйте правила
* Пишите номер правила и получившуюся строку

```
1)  *1 → 1* 
2)  *0 → 0* 
3)  1* → .1* 
4)  0* → .0* 
5)     → *
```
Будем применять подстановки, после `//` пишу комментарий:
```
11001       // исходная строка
*11001      // 5) в начале всегда есть пустая строка
1*1001      // 1)
11*001      // 1) начинаем опять с первого правила
110*01      // 2)
1100*1      // 2)
11001*      // 1)
11001*      // 4) стоп-правило, дальше не будем подставлять
```

Вопрос: как добиться состояния, что `*` в конце не будет? (Можно ли при этом поменять два первых правила местами? А два последних?)

### Итого:

* было -> стало
* всегда с начала
* стоп-точка
* пустые строки в начале 

## Машина Тьюринга

* Лента с ячейками, бесконечная
    * Алфавит символов на ленте + "пусто"
* Каретка (чтение, запись, влево, вправо)
* Набор состояний машины (алфавит состояний)
* Правила (символ на ленте + состояние)
    * символ на ленте (записали)
    * куда передвинулись `<-`, `->`, `⛔` конец работы алгоритма
    * новое состояние
* Начальное состояние: позиция каретки, состояние, содержимое ленты
    
**(символ1, состояние1) -> (символ2, движение, состояние2)**

## Машина Поста

* Лента с ячейками, бесконечная
    * Алфавит из 2 символов: пусто и непусто
* Каретка (чтение, запись, влево, вправо, ? проверка)
* Правила
    * пронумерованы
    * последовательность инструкций с переходами (программа из одних goto)
* Начальное состояние: позиция каретки, номер правила, содержимое ленты

| Оператор | Что делает |
|----|----|
| `V` | ставит метку |
|   | стирает метку |
| `<-` | каретку влево |
| `->` | каретку вправо |
| `? X,Y` | если есть метка, то к правилу Х; если метки нет, к правилу Y |

## Сравнение машины Тьюринга и машины Поста

### Общее

* Бесконечная лента
* Головка/каретка. Читает/пишет и двигается.
* Детерминированность — в каждый момент ровно одно следующее действие.
* Конечный набор инструкций — программа конечна, хотя лента бесконечна.

### Различия

| Признак | Машина Тьюринга | Машина Поста |
|----|----|----|
| Алфавит ленты | Произвольный, может быть много символов | Всего два: «метка» и «пусто» |
| Способ задания программы | Таблица переходов (состояние × символ) | Нумерованный список команд с переходами |
| Понятие состояния | Есть явные состояния (Q0, Q1, …) | Состояний нет, их роль играет номер команды |
| Принцип работы | «В состоянии Q при символе X сделай Y и перейди в Q'» | «Выполни команду N, затем перейди к команде M» |
| Запись/стирание | Может записать любой символ алфавита | Может только поставить или стереть метку |
| Проверка условия | Выбор команды по паре (состояние, символ) | Отдельная команда ? — проверка «есть метка или нет» |
| Остановка | Особое состояние останова (или отсутствие правила) | Команда ! (стоп) |
| Внешний вид программы | Таблица | Список строк |
| Аналогия | Микропроцессор с регистром состояния | Программа на ассемблере с метками и переходами |
