## Числа Фибоначчи

Вспомним, как мы находили $n$-тое число Фибоначчи с помощью рекурсии.

$$   \begin{cases}   fib(0) = fib(1) = 1		 & \\\\   fib(n) = fib(n-1) + fib(n-2)  & \quad n>1  \end{cases} $$  

При рекурсивном решении задачи

```cpp
int fib(int n) {
	if (n == 0 || n == 1)
		return 1;
	return fib(n-1) + fib(n-2);
}
```
Мы получали древовидную рекурсию, для `n=5` нужно 9 вызовов этой функции, а для 20 уже 21891.

<p style="text-align:center"><img alt="" height="200" src="https://stepik.org/media/attachments/lesson/261699/fibonacchi_call.svg" width="436" /></p>

Можно ли решить задачу эффективнее по количеству вычислений? Видно, что одни и те же числа вычисляются много раз и было бы хорошо после первого же вычисления запоминать результат.

Будем запоминать в массив. Здесь применимы два подхода: мемоизация (top-bottom, нисходящее динамическое программирование) и табуляция (bottom-top, восходящее динамическое программирование).

## Нисходящее динамическое программирование (top-bottom. мемоизация)

Реализация почти такая же как в наивной рекурсивной реализации, но добавляется массив `mem`, в который будем **записывать вычисленные данные** по мере их вычисления:

* Сначала проверяем, есть ли уже посчитанное число Фибоначчи.
* Если нет, то для `n` вычисленный результат `fib(n)` сохраняем в `mem[n]`. 

В выражении `fib(n - 1) + fib(n - 2)` какое выражение будет вычислено первым - правое или левое - зависит от компилятора, флагов оптимизации и тп. Но нам это не важно. Предположим, что сначала вычисляется первое слагаемое. При вычислении сначала второго слагаемого *принципиально* в решении ничего не меняется.

*В решении отсутствуют проверки на выход за границы массива. Доучитесь до динамических массивов, выделяйте память динамически и передавайте её в функцию аргументом*.

```cpp
int fib(int n)
{
    // весь массив заполнен 0, числа Фибоначчи 0 не существует
    static int mem[40]; 
    
    // базовый случай
    if (n == 0 || n == 1)
        return 1;
        
    // если уже вычисляли раньше, воспользуемся результатом
    if (mem[n] != 0)
        return mem[n];
        
    // иначе придется вычислить и запомнить
    mem[n] = fib(n - 1) + fib(n - 2);
    return mem[n];
}
```

Из всего дерева мы идем по одной ветке вниз, вычисляя всегда первое слагаемое `fib(5)` → `fib(4)` → `fib(3)` → `fib(2)` → `fib(1)` и по мере обратного подъема записываем вычисленные значения в `mem`. А на следующих вызовах их используем. То есть из дерева вызовов рекурсивных функций останется по сути одна ветвь и небольшие ответвления глубиной 1, в которых используется значение из `mem`.

**Перерисовать самой обе картинки из рекурсии и эту в одном стиле, эта взята из статьи на хабре!**

![](https://habrastorage.org/r/w1560/getpro/habr/upload_files/73d/896/57a/73d89657a57ef3e35beeda64589b8f27.png)

* Код очень похож на предыдущую рекурсивную реализацию.
* До использования не забудьте заполнить массив значением, которое не может быть результатом вычисления. Мы взяли 0, могли взять -1, тоже не является числом Фибоначчи.

## Восходящее динамическое программирование (bottom-top, табуляция)

В предыдущем подходе мы фактически сначала вычислили `fib(0)` и `fib(1)`, потом `fib(2)`, `fib(3)` и так далее. Давайте сразу считать в таком порядке, сразу хранить вычисленные значения в массиве `mem` и использовать их.

```cpp
#define N 40

int fib(int n)
{
    int mem[N] = {1, 1};
    for (int i = 2; i <= n; i++)
        mem[i] = mem[i - 1] + mem[i - 2];
    return mem[n];
}
```

* Нет риска переполнения стека.
* Часто быстрее, так как нет накладных расходов на вызовы функций.
* Можно оптимизировать память (хранить массив вне функции, при множественных вызовах использовать ранее вычисленные значения, досчитывать только недостающие элементы).

### Оптимизация памяти

Как вы видите, нужно только `fib(n - 1)` и `fib(n - 2)` значение. То есть по сути по двум переменным мы считаем третью. Назовем эти переменные `cur` и `prev`, вычислять будем переменную `next`.

```cpp
int fib(int n)
{
    if (n == 0 || n == 1)
        return 1;
    int cur = 1, prev = 1, next;
    for (int i = 2; i <= n; i++){
        next = cur + prev;
        prev = cur;
        cur = next;
    }
    return cur;
}
```
Так что динамическое программирование - это не только "запомнили все в массив", а скорее "стали использовать предыдущие вычисления".

## Пример: Задача о лестнице (Climbing Stairs)

Сколько способов подняться на n-ю ступеньку, если можно шагать на 1 или 2 (следующую ступеньку или перепрыгивать через неё)?

![https://githubusercontent.com/tatyderb/conline_new/refactoring/algo/img/dp_task_locust.png](dp_task_locust.png)

**Никогда не рисуйте таких схем!** Они только запутают решение задачи. Нас интересует не *куда* можно перейти с текущей ступеньки, а **откуда** можно в нее прийти.

![https://githubusercontent.com/tatyderb/conline_new/refactoring/algo/img/dp_task_locust_ok.png](dp_task_locust_ok.png)

На ступеньку 3 можно перейти со ступеньки 2 (шаг на +1) или со ступеньки 1 (шаг на +2). То есть на ступеньку `i` можно перейти со ступеньки `i - 1` или `i - 2`. Если на ступеньку `i - 1` мы могли попасть $K_{i-1}$ различными вариантами и на ступеньку `i - 2` мы могли попасть $K_{i-2}$ различными вариантами то на ступеньку `i` мы можем попасть только с этих двух ступенек, значит $K_{i-1} + K_{i-2}$ различными вариантами.

Количество вариантов будем хранить в массиве `mem`. 

На первую ступеньку можно попасть ровно одним вариантом. На вторую - или сразу прыгнуть снизу на +2 или перейти с первой на +1, то есть 2 разных варианта. 

Или: решим, что изначально кузнечик стоит на ступеньке номер 0. Туда можно попасть ровно 1 вариантом (ничего не делать). На первую можно попасть тоже 1 вариантом (шагнуть с нулевой на +1).

Запишем, как мы попадали на первые ступеньки и на очередную.

```cpp
int steps(int n)
{
    int mem[100] = {1, 1};
    for (int i = 2; i <= n; i++)
        mem[i] = mem[i - 1] + mem[i - 2];
    return mem[n];
}
```
*Кажется, такой код мы уже видели и это числа Фибоначчи.*

## TASKINLINE Плата за проход

*Похожа на предыдущую, но тут мы ищем не количество вариантов, а при имеющейся цене наступания на каждую ступеньку, минимальную цену подъема на самый верх.*

Моряк поднимается по лестнице, состоящей из $n$ ступенек. На каждой ступеньке его поджидают пираты и требуют плату за проход. Стоимость прохода через ступеньку $i$ равна $a_i$. Моряк начинает путь перед первой ступенькой. За один шаг он может: подняться на следующую ступеньку или перепрыгнуть через одну ступеньку. При попадании на ступеньку моряк должен заплатить указанную на ней сумму. Необходимо определить минимальную сумму, которую придётся заплатить, чтобы попасть на последнюю, $n$-ю ступеньку. Плата на последней ступеньке также учитывается.

Дано $n$, далее на другой строке стоимость ступенек $a_i$ через пробел

Например:
```cpp
5
5 2 8 3 6
```

![https://githubusercontent.com/tatyderb/conline_new/blob/refactoring/algo/img/dp_task_step_cost.png](dp_task_step_cost.png)

*Опять видим, что нарисована схема неверно. Надо рисовать как приходим на ступеньку, а не уходим с неё.*

| Ступенька `i` | Стоимость самой ступеньки `a[i]` | Стоимость пути `path[i]` | Комментарий |
|----|----|----|----|
| 0 |  0 | 0 | стоим перед лестницей абсолютно бесплатно |
| 1 |  5 | 5 | на первую ступеньку можно попасть одним способом, шагнув на +1, цена пути равна цене ступеньки |
| 2 | 2 | min(0, 5) + 2 = 2 | на вторую ступеньку можно прыгнуть с нулевой или шагнув с предыдущей, лучше прыгать с нулевой, дешевле! Платим стоимость текущей ступеньки. |
| 3 | 8 | min(5, 2) + 8 = 10 | на эту можно шагнуть или с первой или со второй, дешевле со второй.  Платим стоимость текущей ступеньки. |
| 4 | 3 | min(2, 10) + 3 = 5 | `path[4] = min(path[2], path[3]) + a[4]` |
| 5 | 6 | min(10, 5) + 6 = 11 | `path[5] = min(path[3], path[4]) + a[5]` |

Из анализа таблицы получаем:

* формула перехода на $i$-тую ступень: `path[i] = min(path[i-1], path[i-2]) + a[i]`
* начальные значения `path[0] = 0`, path[1] = a[1]`

## TASKINLINE Последовательность из 0 и 1

Взято с [informatics.mccme.ru](https://informatics.mccme.ru/mod/statements/view.php?id=654&chapterid=207#1), но там требуют печати для N=100, ответ не входит в unsigned long long. Тут все решается в стандартных целочисленных типах.

Требуется подсчитать количество последовательностей длины $1 \le N \le 40$, состоящих из 0 и 1, в которых никакие две единицы не стоят рядом.

Дано $N$, напечатать количество таких последовательностей.

Будем разбирать задачу поэтапно. С ростом $N$ от 1 и далее. Цель: вывести как зная информацию о словах длины $N$ найти количество слов длины $N+1$.

### N = 1

Слов длины 1 ровно 2, это `0` и `1`.

### N = 2

Слова длины 2 получаются приписыванием к слову длины 1 ещё одного символа, 0 или 1.

Было `0`, стало `00` и `01`. То есть, если слово оканчивается на `0`, то из него получается два разных слова, оканчивающееся на `0` и на `1`.

Было `1`, стало только `10`, так как слово `11` содержит две подряд идущих единицы.

### N = i + 1

Пусть у нас есть $K_{i0}$ слов длины $i$, оканчивающиеся на `0` (вида `...0`) и $K_{i1}$ слов длины $i$, оканчивающиеся на `1` (вида `...1`).

Ноль можно приписать в конец как к словам вида `...0`, так и к словам вида `...1`. Получим $K_{i0} + K_{i1}$ слов, оканчивающихся на 0. Это слова вида `...00` и `...10`. $$K_{(i+1)0} = K_{i0} + K_{i1}$$

Единицу можно написать только после нуля. То есть получим слова вида `...01`, слова вида `...11` отбросим. $$K_{(i+1)1} = K_{i0}$$

Всего слов длины $i + 1$ будет $$K_{i+1} = K_{(i+1)0} + K_{(i+1)1}$$

### Реализация

Можете использовать двухмерный массив Nx2, можете использовать два массива длины $N$. Можете оптимизировать по памяти.

Подумайте сколько слов вообще может быть (оценка сверху). Если мы берем все слова из 0 и 1 длины N, то это $2^N$ вариантов.

## TASKINLINE Черепаха

Взято с [informatics.mccme.ru](https://informatics.mccme.ru/mod/statements/view.php?id=656&chapterid=2966#1)

В левом верхнем углу прямоугольной таблицы размером N×M находится черепашка. В каждой клетке таблицы записано некоторое число. Черепашка может перемещаться вправо или вниз, при этом маршрут черепашки заканчивается в правом нижнем углу таблицы.

Подсчитаем сумму чисел, записанных в клетках, через которую проползла черепашка (включая начальную и конечную клетку). Найдите наибольшее возможное значение этой суммы и маршрут, на котором достигается эта сумма.

### Входные данные
В первой строке входных данных записаны два натуральных числа N и M, не превосходящих 100 — размеры таблицы. Далее идет N строк, каждая из которых содержит M чисел, разделенных пробелами — описание таблицы. Все числа в клетках таблицы целые и могут принимать значения от 0 до 100.

### Выходные данные
Первая строка выходных данных содержит максимальную возможную сумму, вторая – маршрут, на котором достигается эта сумма. Маршрут выводится в виде последовательности, которая должна содержать N-1 букву `D, означающую передвижение вниз и M-1 букву `R, означающую передвижение направо. *Если таких последовательностей несколько, черепаха предпочтет прийти к цели сверху.*
