## Надо ли устанавливать программы для курса?

Если не хотите ничего устанавливать сейчас - используйте встроенный редактор Stepik, пока не станет тяжело писать большие программы (задачи про массивы и далее). Тогда вернитесь к настройке рабочего окружения и перестаньте усложнять себе жизнь онлайн-редактором. Хотите сразу писать код, а не настраивать окружение? [Быстрее, к коду и программам](https://stepik.org/lesson/571830/step/1).

**Студенты МФТИ устанавливают компилятор, отладчик, систему контроля памяти и редактор или IDE в первую неделю учебы.**

### Онлайн-редактор Stepik

* ✅ Не нужно ничего устанавливать, уже все работает.
* ✅ Не требует дополнительного места на диске, только ресурсов для работы браузера или мобильного приложения.
* ❌ Маленькое окно редактирования: виден лишь небольшой кусок кода (а программы бывают до 300 строк).
* ❌ Нет дебагера, остается только отладочная печать.
* ❌ В задачах, где нужно написать только часть кода, нельзя изменить скрытую часть: не получится ограничить её выполнение, добавить отладочную печать и т.п.
* ❌ Система контроля памяти (в задачах с частичным кодом) указывает на номера строк, которых нет в вашем коде; первая строка вашего кода - это не строка номер 1 во всей программе. В диагностике указаны номера проблемных строк.
* ❌ Не изучаются реальные инструменты, которые нужны в работе.
    
### Самостоятельная настройка окружения для работы

* ❌ Тратим время на установку программ
* ❌ Программы занимают место на компьютере и другие ресурсы (CPU, память).
* ✅ Окно редактирования во весь экран, в редакторе есть поиск, удобная навигация по коду (переход от вызова функции к её реализации).
* ✅ Есть дебагер в дополнение к отладочной печати.
* ✅ Система контроля памяти указывает номера строк вашей программы, которая всегда вам видна.
* ✅ Изучаешь инструменты, которые будут нужны в дальнейшем обучении и работе.
    
**Навыки работы с терминалом, сборкой, отладкой и анализом памяти переносятся на любой язык, любую ОС и любой проект. Умение же кликать в конкретном онлайн-редакторе Stepik нигде, кроме Stepik, не пригодится.**

Худший вариант: прохождение всего курса с телефона с виртуальной клавиатурой. С телефона удобно читать теорию и проходить синтаксические тренажеры. Для написания программ хотя бы присоедините клавиатуру к телефону!

## Что устанавливаем

Выбор конкретных программ зависит от операционной системы (ОС).

* Текстовый редактор с подсветкой синтаксиса, в котором будем писать текст программы и создавать файлы с тестовыми данными,
* командная строка UNIX (есть в Linux и MacOS, ставится WSL в Windows),
* компилятор,
* инструмент для контроля работы с памятью `valgrind` или `address sanitizer`,
* отладчик (опционально, можно пройти курс без него, используя отладочную печать - основной инструмент для поиска ошибок в программе в этом курсе),
* IDE (опционально) - Integrated Development Environment, интегрированная среда разработки — программа, объединяющая в одном интерфейсе редактор кода с подсветкой, компилятор, отладчик, систему сборки и другие инструменты.

### Командная строка UNIX

**Командная строка** — текстовый интерфейс для управления компьютером, при котором пользователь вводит команды в виде текста, а система их выполняет и выводит результат. Это способ взаимодействия с ОС (в противоположность графическому интерфейсу с окнами и мышью).

**Оболочка (shell)** — программа, которая читает команды, введённые в командной строке, интерпретирует их и запускает нужные программы. Примеры: `bash`, `zsh`, `fish` (Linux/macOS), `PowerShell`, `cmd` (Windows). Часто слово "командная строка" используют как синоним оболочки, хотя технически это разные вещи.

В Linux и MacOS командная строка UNIX уже есть. В Windows мы установим WSL.

### Редактор с подсветкой синтаксиса

Любой, на ваш вкус, который поддерживает ваша операционная система (ОС). Главное - подсветка синтаксиса, чтобы элементы кода (ключевые слова, строки, комментарии, числа) выделялись разными цветами. И показ номеров строк. Так удобнее читать код и искать ошибки.

* [Notepad++](https://notepad-plus-plus.org/) (только Windows)
* [VSCode](https://code.visualstudio.com/) - различные ОС
* [vim](https://www.vim.org/download.php) - различные ОС. Можно поставить графическую версию или запускать в командной строке. Нужно [научиться с ним работать](https://stepik.org/lesson/250622/step/1).


### Компилятор (и линкер)

Программа, который переводит код, написанный на языке Си в исполняемый модуль. 

* `gcc` (от GNU Compiler Collection)
* `clang` - в него встроен Address Sanitizer

### Отладчик (опционально)

Отладчик (debugger) - инструмент, позволяющий выполнять программу пошагово, ставить точки останова (breakpoints), просматривать значения переменных и состояние стека вызовов, чтобы находить причины ошибок в логике работы программы.

* `gdb`

Или научимся пользоваться отладочной печатью. 


### Утилиты для контроля памяти

Ищут ошибки работы с памятью: утечки, выход за границы массива, использование освобождённой памяти. Ставим одну на выбор.

* **Valgrind** - больше возможностей (динамическая проверка, во время исполнения программы). Не работает на MAC. На Windows требует установки WSL.
* **Address Sanitizer** - статическая проверка, встроен в компилятор.

### IDE

Все вышеперечисленное, в одном месте, в одном окне, связанное друг с другом. Это интегрированная среда разработки. Некоторые открывают один проект и все файлы этого проекта связаны друг с другом (лучше не надо). Другие разрешают открыть директорию и в ней писать каждую программу в отдельном файле - это наш выбор.

* **VSCode** - будет дана инструкция.
* **Geany**
* **CodeBlock**
* **Clion** (проблема с лицензией в части стран).
* **Visual Studio Community** - не советуем, большие требования к железу, заточена под проект, то есть "пишем одну программу во многих файлах", а у нас будет "пишем много программ, каждую в своем файле".

Выберите IDE, которая требует мало ресурсов.

Все это можно получить, выбрав один из вариантов, по убыванию "крутости":

* Linux на отдельном компьютере или дополнительной операционной системой на вашем компьютере. В Mac OS проблемы с установкой `valgrind`, который нам понадобится. (Выходит за рамки данного курса).
* Linux в качестве виртуальной машины. (Выходит за рамки данного курса).
* **UNIX-терминал + IDE** (например WSL + VSCode в Windows) - будет дана подробная инструкция.
* UNIX-терминал + текстовый редактор.
* Онлайн-IDE с `valgrind`. Например, [https://replit.com/languages/c](https://replit.com/languages/c) или [https://www.onlinegdb.com/online_c_compiler](https://www.onlinegdb.com/online_c_compiler) - уж лучше встроенный редактор Stepik.
* Ничего не устанавливать, использовать встроенный редактор Stepik.

Обратите внимание, что "командную строку Unix/Linux" вы уже имеете в MacOS и можете получить в Windows, установив WSL.

Почему Linux предпочтителен для разработки? Много удобных бесплатных программ с меньшими требованиями к железу.

## Linux: gcc + valgrind

Запустите терминал. Дальше будем работать в командной строке.

* Если не знаете, какой дистрибутив у вас стоит, запустите
```
cat /etc/os-release
```

### Установка `gcc` и `valgrind`

Проверьте, стоят ли у вас нужные программы. В терминале наберите команды:
```
gcc --version
valgrind --version
```
Если вывод содержит версию, то программа установлена. Иначе устанавливаем и далее проверяем, что установилось корректно.

Для установки программ и системных изменений нужно запускать эти команды с `sudo`.
 
#### Debian / Ubuntu (пакетный менеджер apt)

```
sudo apt update
sudo apt install build-essential gdb valgrind
```

#### Fedora / RHEL / CentOS (dnf/yum)

```cpp
# Fedora
sudo dnf install gcc valgrind

# CentOS 7 (старый, с yum)
sudo yum install gcc valgrind
```

**Важное замечание для CentOS/RHEL 7:** Стандартные репозитории содержат очень старую версию GCC (4.8.5). Если нужен более новый компилятор, используйте `devtoolset`:

```cpp
sudo yum install centos-release-scl
sudo yum install devtoolset-11-toolchain
scl enable devtoolset-11 bash
```

#### openSUSE (zypper)

```cpp
sudo zypper install gcc valgrind
```

#### Arch Linux / Manjaro (pacman)

```cpp
sudo pacman -S gcc valgrind
```

*Пишите уточнения и замечания по инструкциям в комментариях.*

## Linux: устанавливаем IDE

IDE - это продвинутый редактор с возможностью использовать уже установленные компилятор и отладчик. Инструкции для **VS Code**.

#### Универсальный способ через Snap

```
sudo snap install code --classic
```

#### Для Ubuntu / Debian (официальный репозиторий)

Этот метод предпочтителен, если вы хотите получать обновления вместе с системой и избежать возможных проблем с песочницей Snap.

1. Установите зависимости и ключ Microsoft:

```
sudo apt update
sudo apt install -y wget gpg
wget -qO- https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor > packages.microsoft.gpg
sudo install -D -o root -g root -m 644 packages.microsoft.gpg /etc/apt/keyrings/packages.microsoft.gpg
rm packages.microsoft.gpg
```

2. Добавьте репозиторий и установите:

```
echo "deb [arch=amd64,arm64,armhf signed-by=/etc/apt/keyrings/packages.microsoft.gpg] https://packages.microsoft.com/repos/code stable main" | sudo tee /etc/apt/sources.list.d/vscode.list
sudo apt update
sudo apt install code
```

#### Для Fedora / RHEL / openSUSE

Скачайте `.rpm` пакет с официального сайта и установите через терминал:

```
sudo rpm -i code-*.rpm
```
Или используйте менеджер пакетов вашего дистрибутива (`dnf`, `zypper`)

## MacOS: все вместе с VS Code

В MacOS невозможна работа `valgrind`. Поэтому устанавливаем `AddressSanitizer`.


| Инструмент	| Назначение |
|----|----|
| `clang` |	Компилятор (входит в Xcode CLT) |
| `AddressSanitizer` |	Аналог valgrind, встроен в clang |
| `VS Code` |	Редактор кода, IDE |

Все команды выполняем в терминале.

* Устанавливаем `clang` в составе Xcode CLT
```
xcode-select --install
```
Проверьте, что `clang` установлен:

```
clang --version
```

* Устанавливаем VS Code через Homebrew:

```bash
brew install --cask visual-studio-code
```

*Если у вас MacOS, ищите/напишите более подробную инструкцию в комментариях к шагу.*

## Windows: настраиваем WSL

Без командной строки тяжело запускать программу с большими тестами и нельзя будет запустить `valgrind`. Задача будет работать на вашем компьютере (без проверок `valgrind`) и не будет проходить проверку в курсе (`valgrind` показал ошибку). Тяжело найти ошибку в своем решении.

Поставим на Windows командную строку Linux. Что ставить, зависит от версии Windows.

**Запишите и запомните свой логин и пароль при установке. Он понадобится на следующем шаге.**

* На Windows 11 (если что, берите гайды по windows-10)
    * [https://vc.ru/dev/744877-kak-ustanovit-wsl-na-windows-11](https://vc.ru/dev/744877-kak-ustanovit-wsl-na-windows-11) на русском, в картинках с рамочками и стрелочками.
* На Windows 10 рекомендуем установить **WSL** (Windows Subsystem for Linux) или **WSL2**. На нем можно делать задачи всех курсов МФТИ по С, в том числе курс по IPC. 
    * [Установка WSL на Windows 10](https://docs.microsoft.com/ru-ru/windows/wsl/install-win10)
    * [Установка WSL на Windows 10 еще одна инструкция](https://g-ek.com/kak-zapustit-bash-v-windows-10)
    * [Video]() - Нужно найти нормальное видео, желательно на русском.
* На Windows 7 или 8 установите **cygwin**. На курсе, изучающим IPC UNIX, `cygwin` будет не достаточно.
    * [cygwin](https://cygwin.com/install.html)
    * [Video](https://www.youtube.com/watch?v=2csABC85onI) - установка
    
В WSL могут быть проблемы с настройкой интернета. [Как настроить ssh в bash](https://superuser.com/questions/1111591/how-can-i-ssh-into-bash-on-ubuntu-on-windows-10)

**Если WSL в Windows установить не удалось, то ставим компилятор `clang` и используем `address sanitizer`**.

## Где искать файлы Windows в командной строке Linux

* `\` - в Windows, `/` - в Linux,
* Из командной строки в **WSL** файл Windows `C:\work\hello.c` находится в `/mnt/c/work/hello.c`
    * диск Windows нужно искать в `/mnt/имя_диска`
* Из командной строки **cygwin** файл Windows `C:\work\hello.c` находится в `/cygdrive/c/work/hello.c`   
    * диск Windows нужно искать в `/cygdrive/имя_диска`

## Проверка: компиляция и запуск программы

* Создайте файл `hello.c` и скопируйте в него следующий текст. Не забудьте сохранить этот файл после изменения.

```cpp
#include <stdio.h>

int main()
{
    printf("Hello, world!\n");
    
    return 0;
}
```

### Скомпилируйте файл

В командной строке наберите (в зависимости от установленного компилятора)

* `gcc`:

```
gcc hello.c -o hello.exe
```
* `clang`:
```
clang hello.c -o hello.exe
```

В текущей директории должен появиться файл `hello.exe`.

### Запустите файл

* Linux (в том числе WSL в Windows или mingw), MacOS:

```cpp
./hello.exe
```
* Windows (PowerShell или cmd):
```cpp
hello.exe
```

Должно напечататься `Hello, world!`.
