## Аналоги printf и scanf

Существуют функции, аналогичные `printf` и `scanf`, но работающие с любыми потоками или строками, а не столько со stdout и stdin.

```cpp
 #include <stdio.h>

int printf(const char *format, ...);
int fprintf(FILE *stream, const char *format, ...);
int dprintf(int fd, const char *format, ...);
int sprintf(char *str, const char *format, ...);
int snprintf(char *str, size_t size, const char *format, ...);
```

`printf("hello")` это `fprintf(stdout, "hello");

Посмотрим, как в имени функции кодируется, куда собираемся писать:

| *Функция* | *Аргумент КУДА* | *куда* |
|---|---|---|
| printf |  нет | `stdout` |
| <b>f</b>printf | `FILE * stream` | поток |
| <b>d</b>printf | `int fd` | файловый дескриптор |
| <b>s</b>printf | `char * str` | строка |
| <b>sn</b>printf | `char * str, size_t size` | строка с контролем переполнения |

И по тому же принципу построен набор функций, аналогичных scanf:

```cpp
int scanf(const char *format, ...);
int fscanf(FILE *stream, const char *format, ...);
int sscanf(const char *str, const char *format, ...);
```

## Специфичные функции

Функции семейства printf и scanf универсальные. Они понимают что и как им нужно читать и писать, разбирая форматную строку.

Существуют узкоспециализированные функции чтения и записи символа и строки.

```cpp
#include <stdio.h>

int fputc(int c, FILE *stream);
int putc(int c, FILE *stream);
int putchar(int c);

int fputs(const char *s, FILE *stream);
int puts(const char *s);
```

| *Функция* | *Что делает* |
|---|------|
| fputc | записывает символ *c*, преобразованный к `unsigned char` в *stream* |
| putc | то же, что fputc, но может быть макросом |
| putchar | `putc(c, stdout)` |
| fputs | записывает строку *s* и '\n' в *stream* |
| puts | `fputs(s, stdout)` |

Для ввода:

```cpp
#include <stdio.h>

int fgetc(FILE *stream);
int getc(FILE *stream);
int getchar(void);
int ungetc(int c, FILE *stream);

char *fgets(char *s, int size, FILE *stream);
char *gets(char *s);
```

| *Функция* | *Что делает* |
|---|------|
| fgetc | читает символ *c*, преобразованный из `unsigned char` к `int` в *stream* |
| getc | то же, что fgetc, но может быть макросом |
| getchar | `getc(c, stdin)` |
| ungetc | возвращает обратно в поток *stream* символ *c* |
| fgets | читает строку длиной не более *size*-1 символов из *stream* и записывает ее в *s* |
| gets | не используйте эту функцию |

Старайтесь не использовать `ungetc`. Эта функция не предназначена для многопоточной программы.

Почему не рекомендуется использовать *gets* ? Потому что вы не контролируете длину введённых данных и может возникнуть переполнение строки *s*.

## Почему int?

Почему fgetc возвращает int, а не unsigned char?

Функция должна вернуть ASCII-код прочитанного символа. Это числа от 0 до 255. То есть unsigned char. 

Но функция так же должна вернуть возникла ошибка или нет. Это 0 или 1. Хватит 1 бита.

Два значения вернуть нельзя. Зато можно скомпоновать из двух маленьких чисел одно большое. Если ошибки не было, запишем в младшие 8 бит ASCII-код почитанного символа, а в остальные биты большого числа запишем нули. Если мы преобразуем возвращенный результат к unsigned char, то получим этот ascii-код. 

В случае ошибки неважно что мы пишем в младшие 8 бит (символ не прочитался!), но в старшие биты пишем какое-нибудь число, не равное 0.

Почему код работает неверно?
```cpp
char c;
while((c = getchar()) != EOF)
	putchar(c);
```
Потому что EOF - это НЕ ascii-код. Это прежде всего ненулевая часть в старших битах, которые мы выкинули при преобразовании из int в char в выражении `c = getchar()`. То есть мы потеряли информацию - была считан очередной символ или нет (EOF или другая причина).

По стандарту EOF это -1. То есть если мы прочитали во входном потоке символ c ascii-кодом  `(unsigned char)(-1)`, то его можно ошибочно принять за EOF.

Если же с объявлен как `unsigned char`, при сравнении его с EOF оба числа будут преобразованы к `unsigned int`. Выражение `(unsigned int)c` тогда будет иметь все 0 в старших байтах, а `(unsigned int)EOF` будет иметь ненулевые старшие байты и `с` никогда не станет равным EOF. Получим бесконечный цикл.

## Буферизация

Рассматривая работу с потоками нужно помнить, что взаимодействие с внешними устройствами происходит гораздо медленнее, чем вычисления в памяти и даже чтение и запись на диск. Ввод и вывод может являться узким местом программы. Для ускорения процесса используют буферизацию. То есть обмен данными с внешними устройствами организован через память для временного хранения данных (**буфер**). 

При вводе или выводе данных одно устройство или процесс пишет данные в буфер, а другой - читает из него. Процесс, который записал что-то в буфер, может сразу же продолжать работу дальше, не дожидаясь, пока данные будут обработаны. С другой стороны, процесс после обработки порции данных может сразу брать следующую (уже подготовленную) порцию из буфера.

Например, вы на семинаре в Долгопрудном обнаружили, что забыли 3 тетради с заданиями в Зюзино. Дорога в одну сторону занимает 2 часа. Конечно, можно поехать в Зюзино, взять 1 тетрадку, приехать в Долгопрудный, отдать тетрадь семинаристу и поехать за следующей. А можно поехать в Зюзино, взять эти 3 тетради в рюкзак, туда положить еще пару учебников (могут понадобиться на семинаре), словарь-минимум по английскому языку (будем учить слова в дороге), бутерброд, и еще много вещей, которые будут нужны при сдаче задания в Долгопрудном. В Долгопрудном мы будем доставать их из рюкзака (нашего буфера), а не ездить за каждой вещью обратно в Зюзино.

## Сброс буферов

Еще один пример буферизации - это сливной бачок унитаза. У нас в нем накапливаются данные (вода) и по некоторому событию (нажали кнопку слива воды) данные из буфера попадают в выходное устройство (слив).

Аналог нажатия на кнопку сливного бачка - функция
```cpp
int fflush(FILE * stream);
```
	* Для выходного потока *stream* принудительно записывает буферизованные данные (из пространства пользователя) или обновляет поток, используя функцию `write`;
	* Для входного потока, связанного с терминалами или конвейерами, читает/записывает все данные из буфера;
	* Для входного потока, связанного с файлами, по которым делается `fseek`, лишние прочитанные данные, которые не были востребованы, выбрасывается и в буфер пишется новая порция данных.
